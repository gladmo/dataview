# 数据视图交互与视觉风格对齐 Grafana 仪表盘范式

## 背景

数据视图（Data View）已具备 12 列网格、拖拽/缩放、表格/图表双模式与 mutation 确认等能力，但交互仍停留在“表单 + 一次性执行”：没有自动刷新、没有“上次刷新时间”反馈、结果面板缺少数据规模信息、空结果无提示；列表页搜索独占一整行工具栏；编辑器表单平铺、变量行无列头、查询卡片无法一眼区分 query 与 mutation。用户要求参考 Grafana 优化样式与交互，同时保持与本项目（shadcn-vue + Tailwind 令牌、h-9 紧凑工具栏、ghost 图标按钮、i18n 全量覆盖）风格统一。

## 决定

- Runner 改为 Grafana 仪表盘范式：顶部 h-8 控制条承载“查询”按钮、自动刷新间隔选择（off/5s/10s/30s/1m/5m/15m）、运行中耗时或“更新于 N 前”状态、变量行折叠开关与布局编辑开关；执行期间控制条下缘显示 2px 不定态进度条，代替原先的整段虚线提示。变量区降为无边框次级条（bg-muted/10），布尔变量用 Switch 替代裸 checkbox。结果区独立滚动，工具栏与变量条保持可见；面板头部悬停显示 表格/图表 图标切换，面板底部显示“行 · 列”统计，空结果显示“暂无数据”。自动刷新由纯函数模块 `lib/dataView/dataViewAutoRefresh.ts` 驱动：以“上次运行起点”为锚的 setTimeout 链（慢查询不叠帧）、`document.hidden` 时跳过、unmount 全量清理；沿用现有 12 列网格与手势逻辑不变。
- 列表页：搜索框并入标题工具栏（省一整行），条目改为两行卡式行（名称 + 查询数徽标 / 描述），图标改为靛蓝色底 badge，悬停动作保留，右键菜单与删除确认流程不变。
- 编辑器：拆成“基本信息 / 变量 / 查询”三个带统一 h-8 分区头的卡片；变量区改为带列头的对齐网格（名称/标签/类型/默认值/必填），“SQL”按钮改标“从 SQL 提取”；查询卡片对 mutation 加琥珀色边框与徽标，预览按钮改 secondary 变体提升可见性。
- 所有新文案进入 `dataView.*` 命名空间并同步全部 9 个含该块的 locale（en/es/it/ja/ko/pt-BR/tr 用英文，zh-CN/zh-TW 用中文，zh-TW 沿用其块内既有的简体同文惯例）；间隔选项（5s/1m…）为纯符号，不做本地化。

## 替代方案

- 引入 react-grid-layout 式第三方 Vue 网格库换取更多面板手势：现有自研手势（rAF 节流拖拽 + 垂直压缩）已覆盖需求，引入依赖与测试成本不成比例，放弃。
- 把自动刷新做成视图级持久配置（存进 DataView 实体）：会让共享链接的读者被动执行作者设定的轮询，刷新策略属于查看者会话状态，留在组件本地，放弃持久化。
- 面板级单查刷新（Grafana 的 per-panel query）：当前执行 API 以视图为单位批量执行，单面板刷新需后端改造，超出本次样式/交互优化范围，不做。
- 在 DataViewPage 页头放运行控制：Runner 同时服务分享页（embedded），控件必须随组件走，避免两套头，放弃。

## 验证

- 新增 `dataViewAutoRefresh.spec.ts` 9 例（间隔表有序且唯一、id 解析、锚定延迟钳制、短时长格式化）全绿。
- `DataViewPage.spec.ts` 6 例（行渲染/搜索过滤/空态/编辑直达/删除确认流）在改版后未改动断言全部通过，确认列表行为与可测选择器未回归。
- 全量 vitest、vue-tsc typecheck、oxlint（仅存两处既有 warning，均在本文件未触碰的旧代码）通过；oxfmt 格式化无差异。
